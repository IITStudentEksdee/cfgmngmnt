## Этап 2. Сбор данных (формат apt)

Реализовано: загрузка Packages-индекса репозитория apt по URL (urllib + gzip,
стандартная библиотека), разбор станз (записей) индекса, сравнение версий по Debian Policy
(проверено на векторах из testsuite dpkg, см. `tests/test_versions.py`),
разбор поля Depends с ограничениями версий и альтернативами
(`tests`, `tests`).

### 1. Пакет с заданной версией (реальный репозиторий Ubuntu 24.04 noble)

```
$ python -m depgrapher -p curl -s http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz -v 8.5.0-2ubuntu10
== Загрузка Packages-индекса: ... ==

(exit=0)
```

## Этап 3. Основные операции: граф зависимостей (BFS с рекурсией)

Граф строится рекурсивным BFS (функция `_bfs_layer` обрабатывает один слой
и вызывает саму себя для следующего). Циклические зависимости обнаруживаются
по рёбрам к уже посещённым узлам и не добавляют новые узлы, поэтому обход
гарантированно завершается; «алмазы» (общие зависимости) от настоящих
циклов отличает `Graph.describe_cycles()`.

### Тестовый репозиторий (--mode file)

**1. Цепочка** (`testrepos/chain.txt`, пакет A):

```
Узлов: 4, рёбер дерева: 3, обратных рёбер: 0
Порядок обхода (BFS): A -> B -> C -> D
Циклических зависимостей: нет
```

**2. Альтернативы** (`testrepos/diamond.txt`, A: B|C): выбрана первая
удовлетворяемая альтернатива B; D — самая высокая версия, удовлетворяющая
`D(>=1.0)`:

```
Узлов: 3, рёбер дерева: 2, обратных рёбер: 0
Порядок обхода (BFS): A -> B -> D
```

**3. Цикл** (`testrepos/cycle.txt`, A -> B -> C -> A, плюс A -> D):

```
Узлов: 4, рёбер дерева: 3, обратных рёбер: 1
Порядок обхода (BFS): A -> B -> D -> C
Обнаружены циклические зависимости:
1. A -> B -> C -> A
```

**4. Самозависимость + ограничения версий** (`testrepos/deep.txt`):
B разрешается как 2.0 (самая высокая), E -> E — цикл длины 1,
ребро C -> B (B уже посещён) обратным рёбром считается, но циклом — нет:

```
Узлов: 5, рёбер дерева: 4, обратных рёбер: 2
Порядок обхода (BFS): A -> B -> C -> E -> D
Обнаружены циклические зависимости:
1. E -> E
```

**5. Нерешаемая зависимость** (`testrepos/broken.txt`, A: X(>=2.0), при X 1.0):

```
Зависимости, не удовлетворённые репозиторием:
- A: X (>= 2.0)
```

**6. Ошибки** (код выхода 4):

| Сценарий | Результат |
|---|---|
| Пакет не найден | `Ошибка репозитория: пакет 'Z' не найден в репозитории; всего пакетов: 4` |
| Версия не найдена | `Ошибка репозитория: версия '2.0' пакета 'A' не найдена в репозитории; доступные версии: 1.0` |

### Реальный репозиторий (Ubuntu noble), пакет curl

```
Узлов: 32, рёбер дерева: 31, обратных рёбер: 46
Порядок обхода (BFS): curl -> libc6 -> libcurl4t64 -> zlib1g -> ... -> libdb5.3t64
Обнаружены циклические зависимости:
1. libc6 -> libgcc-s1 -> libc6
```

Несколько слов о цикле libc6 ↔ libgcc-s1: он существует и в реальном
репозитории Ubuntu (libc6 Depends: libgcc-s1; libgcc-s1 Depends: libc6).
apt допускает такие взаимные зависимости, поскольку пакеты устанавливаются
одновременно; инструмент корректно фиксирует цикл и не зацикливается.

### Итог

- граф зависимостей с учётом транзитивности строится алгоритмом BFS
  с рекурсией (`src`);
- циклические зависимости обрабатываются: обход завершается, циклы
  перечисляются (включая цикл длины 1), «алмазы» циклами не считаются;
- режим тестирования (--mode file) продемонстрирован на 6 различных случаях.

## Этап 4. Визуализация: PNG, SVG и ASCII-дерево

Визуализация реализована **только на стандартной библиотеке**
(`src`):

- **PNG** — собственный растреризатор: растровый шрифт 5x7 (A-Z, 0-9,
  знаки), примитивы rect/line/стрелка/текст, кодирование PNG через
  `struct` + `zlib` (8 бит RGB, фильтр «None», CRC32 в каждом чанке);
- **SVG** — векторный аналог (XML, маркеры-стрелки, пунктир для циклов);
- **ASCII-дерево** — опция `-a tree`: дерево BFS-зависимостей
  (символы ├──/└──) со списком циклов в конце.

### Демонстрация (testrepos)

**chain.txt, пакет A** (`-a tree`):

```
== ASCII-дерево зависимостей ==
A 1.0
└── B 1.0
    └── C 1.0
        └── D 1.0

== Визуализация графа ==
PNG: out/chain.png (784x134 px, 1677 байт)
SVG: out/chain.svg (2068 байт)
```

**cycle.txt, пакет A** (ASCII-дерево + список циклов):

```
A 1.0
├── B 1.0
│   └── C 1.0
└── D 1.0

[цикл] A -> B -> C -> A
```

**deep.txt, пакет A**: самозависимость E -> E отображается красным
(обратное ребро), PNG out/deep.png (2267 байт).

**broken.txt, пакет A**: неразрешённая зависимость выводится на
изображение красным текстом («UNRESOLVED: A -> X (>= 2.0)») и в консоль.

### Реальный репозиторий (Ubuntu noble), пакет curl

```
== Визуализация графа ==
PNG: out/curl.png (1828x934 px, 42602 байт)
SVG: out/curl.svg (19152 байт)
```

Появились две зависимости, не удовлетворённые репозиторием:

```
Зависимости, не удовлетворённые репозиторием:
- librtmp1: libnettle8
- libssh-4: libssl3 (>= 3.0.0)
```

Проверка по Packages-индексу: в noble нет пакетов `libnettle8` и
`libssl3` — только `libnettle8t64` и `libssl3t64` (переход на t64),
а `librtmp1` и `libssh-4` зависят именно от старых имён. apt
закрыл это переходными пакетами с `Provides`; инструмент корректно
фиксирует «висящие» зависимости.

### Тесты

- `tests/test_render.py` (9 тестов): структура ASCII-дерева, отметка
  циклов; PNG — сигнатура, согласованность размеров, цвет пикселей
  внутри/на границе карточек, расшифровка одиночного пикселя;
  SVG — валидность XML и наличие узлов; раскладка — 4 столбца в
  цепочке A->B->C->D.
- Все 33 теста пакета проходят.

### Итог

- граф визуализируется в PNG (растреризатор на struct+zlib), SVG
  (XML) и ASCII-дереве — без единой сторонней библиотеки;
- карточки пакетов, стрелки зависимостей и красная подсветка
  циклических рёбер различимы в обоих графических форматах;
- режим `-a tree` выводит читаемое дерево с пометками циклов.

## Этап 5. Документация и финальные тесты

### Заполнение пробелов в покрытии

Добавлены два отсутствующих тестовых модуля:

- `tests/test_cli.py` (17 тестов): значения по умолчанию, все 6
  параметров сразу, эпоха в версии; ошибки argparse (код 2) —
  пропущенный обязательный аргумент, некорректные пакет/версия/
  режим/ASCII/расширение выходного файла; согласованность параметров
  (ConfigError — код 3); коды выхода `main()` (2 и 3).
- `tests/test_testrepo.py` (8 тестов): полный разбор (ограничения
  версий, альтернативы, пустые части), комментарии, имена с цифрами;
  ошибки с указанием `файл:строка` (некорректная строка, версия,
  зависимость); чтение реального файла и отсутствующего.

По ходу тестов выявлены и исправлены два замечания:

1. В тестовом репозитории строка пакета **без двоеточия**
   (`D 1.0` — «нет зависимостей») ранее отклонялась; регулярное
   выражение `testrepo.py` исправлено: часть «`: Зависимости`»
   стала опциональной. Задокументировано в README.
2. Проверено, что `not-a-version:` — *допустимая* Debian-версия
   (upstream может заканчиваться `:`), поэтому тест невалидной
   версии использует `B .5: C` (начинается с точки — запрещена).
